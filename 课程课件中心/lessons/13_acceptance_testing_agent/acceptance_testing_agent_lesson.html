02:00 - 05:00
Why It Matters

验收测试不是找茬，而是确认能不能交付

产品经理做验收时，最怕只凭印象说“差不多能用”。真正可靠的验收，需要把需求、功能、状态、数据、异常和证据连接起来。

一句话：验收测试要回答“这个版本是否达到交付标准，以及还剩哪些风险”。

人工随手验

  • 想到哪里点哪里
  • 截图散落，结论难复查
  • 容易漏掉异常和边界
  • 报告写得像主观感受

AI Agent 验收

  • 先制定测试范围和用例
  • 每个关键结果留证据
  • 失败、阻塞、未测分开记录
  • 直接生成 MD 和 PDF 报告

Report Template

一份老板能看的验收报告，应该长什么样？

测试报告不能只写“功能正常”。它要说明测了什么、怎么测的、结果如何、证据在哪里、还有哪些风险。

模板重点：基本信息、范围、标准、用例、缺陷、截图证据、结论、上线建议。
# 验收测试报告 1. 报告基本信息 2. 验收范围 3. 验收标准 4. 测试用例汇总 5. 缺陷与风险 6. 截图证据 7. 测试结论 8. 上线建议 9. 附录：环境、文件、日志

Prompt & Evidence

实操输入：让 Agent 按流程验收

提示词里一定要明确项目路径、测试对象、测试范围、证据要求和输出格式。否则 AI 很容易只做泛泛检查。

关键句：不要只给主观评价，要有操作步骤、实际结果和证据。

保留什么证据

  • 关键入口
  • 关键状态
  • 关键结果
  • 关键问题

证据形式

  • 页面截图
  • 文件路径
  • 日志片段
  • 错误提示

Result & Deliverable

结论要分清，交付要成文件

回顾重点：这节课的价值

第一，AI Agent 验收不是随机点页面，而是从测试范围到证据链的完整流程。

第二，报告必须包含用例、结果、缺陷、截图和上线建议。

第三，测试前准备账号、Key、权限和测试数据；测试后复核失败项、阻塞项和截图证据。
