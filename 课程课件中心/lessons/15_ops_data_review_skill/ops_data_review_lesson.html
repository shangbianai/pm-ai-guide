WHY

运营复盘不是数据罗列

很多复盘的问题，不是数据不够，而是只有数字，没有判断。老板真正需要的是：这组数据意味着什么，要不要动，怎么动，先动哪里。

表现怎么样

指标健康还是预警？同比环比是否异常？增长是结构性变化，还是一次性波动？

为什么这样

问题发生在哪个环节？是渠道质量、产品体验、活动规则，还是用户结构变化？

接下来怎么办

给 P0/P1/P2 行动方案，说明负责人、时间点、预期效果，以及哪些事先不要做。

好的数据复盘，最终不是“我分析了很多”，而是“我们接下来应该这样做”。
WHAT

这个 Skill 能做什么？

它把产品上线后的运营数据，整理成一份结构化复盘报告：有指标仪表盘、有漏斗分析、有留存和商业化判断，也有问题诊断和行动计划。

1

读数据

接收 UV、PV、DAU、转化率、留存、收入、反馈。

2

拆链路

用 AARRR 看获客、激活、留存、变现和推荐。

3

看体验

用 HEART 补充满意度、参与度、采纳率。

4

找根因

用趋势、交叉分析、5-Why 定位问题。

5

出报告

通过模板和脚本生成稳定的 HTML 报告。

INPUTS

使用前，准备四类输入

复盘质量不只取决于 AI，也取决于你给它什么材料。最关键的是产品背景、上线信息、运营数据和反馈材料。

产品与版本

产品名称、功能简介、上线时间、渠道。让 AI 先知道这次复盘讨论的是哪个产品、哪个版本、什么业务背景。

核心数据

UV、DAU、转化、留存、收入、NPS。不要只给总数，最好给上期、本期、环比、渠道和漏斗拆分。

业务材料

PRD、活动方案、用户反馈、客服记录。帮助 AI 判断数据变化背后的业务事件。

复盘重点

增长、活跃、转化、留存、商业化。告诉 AI 这次最需要老板决策的方向。

AARRR

AARRR：增长漏斗，也叫海盗指标

AARRR 来自 Dave McClure 的 Pirate Metrics，因为 Acquisition、Activation、Retention、Revenue、Referral 连起来像“AAARRR”的海盗喊声，所以常被叫作海盗指标。

运营角度看，它帮我们把“用户生命周期”拆开：用户从哪来、有没有体验到价值、是否回来、是否付费、是否推荐。

五个阶段

  • Acquisition 获客：渠道带来了多少用户，质量如何
  • Activation 激活：用户是否完成首次核心体验
  • Retention 留存：用户是否持续回来
  • Revenue 变现：用户是否带来收入，收入效率如何
  • Referral 推荐：用户是否分享、邀请、形成口碑传播
USE CASE

AARRR 能帮运营复盘做好什么？

找最大瓶颈

不要平均优化所有环节，先看漏斗里掉得最厉害的地方。

判断渠道质量

不只看新增数量，还要看渠道用户的留存、转化和 LTV。

对齐增长动作

明确当前应该做获客、激活、留存、变现，还是推荐。

常见问题AARRR 的切入点可能行动
新增涨了，收入没涨获客质量、激活、付费转化调整渠道投放，优化首次体验和付费路径
活动带来很多用户，但很快流失激活和留存优化核心价值触达，设置次日/7日召回动作
老用户活跃下降留存、推荐、功能使用深度做用户分群，找到沉默原因和召回策略
HEART

HEART：Google 的用户体验度量框架

HEART 是 Google 提出的体验指标框架，用来把“用户体验好不好”拆成可观察的信号。它和 AARRR 不冲突：AARRR 看业务链路，HEART 看体验健康度。

运营角度看，HEART 可以帮我们解释为什么某个环节掉了：是满意度问题、参与度问题、采纳率问题，还是任务完成率问题。

五个维度

  • Happiness：满意度、NPS、用户评价
  • Engagement：使用频率、时长、深度
  • Adoption：新功能采纳率、功能渗透率
  • Retention：用户是否持续回访
  • Task Success：任务完成率、错误率、阻塞点
USE CASE

HEART 能帮运营复盘做好什么？

解释体验问题

当转化或留存下降时，用满意度、任务成功率、错误率解释原因。

衡量新功能效果

看功能采纳率、功能渗透率和核心任务完成率，而不只看上线了没有。

连接反馈和数据

把 NPS、客服记录、用户评价和实际行为数据放到同一张图里看。

体验信号运营解释动作方向
NPS 下降，投诉集中用户主观感受变差，可能影响口碑和复购聚类投诉主题，先处理高频痛点
功能采纳率低用户不知道、看不懂，或价值不够强优化入口、引导、命名和场景提示
任务成功率下降路径变复杂，或新规则增加理解成本简化流程，补充错误提示和兜底路径
FRAMEWORK

AARRR 看链路，HEART 看体验

一个好复盘通常需要两副眼镜：一副看业务增长链路，一副看用户体验健康度。

AAARRR
  • 获客：用户从哪里来，渠道质量如何
  • 激活：用户有没有完成首次核心体验
  • 留存：用户会不会回来，在哪一天掉队
  • 变现：收入效率、付费转化、LTV/CAC
  • 推荐：分享、邀请、口碑传播是否成立
HHEART
  • Happiness：满意度、NPS、用户评价
  • Engagement：使用频率、时长、深度
  • Adoption：新功能采纳率、功能渗透率
  • Retention：用户是否持续回访
  • Task Success：任务完成率、错误率、阻塞点
IMPLEMENTATION

这个 Skill 是怎么实现的？

它不是让模型临时手写网页，而是先产出结构化 JSON，再用固定模板和脚本生成稳定报告。
