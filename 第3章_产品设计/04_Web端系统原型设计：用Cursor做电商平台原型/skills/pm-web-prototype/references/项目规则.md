# AI 原型设计项目规则

## 1. 课程定位

本课程不是只演示某个 AI 工具，而是训练一套可复用的原型设计工作流：需求输入、项目规则、低保真、高保真、可点击交互、验收清单和交付资料。

## 2. 统一业务对象

- 商品：名称、分类、价格、规格、库存、安全线、上下架状态。
- 订单：支付、制作、取餐、退款、异常、取餐码、门店。
- 会员：等级、积分、券包、历史订单、标签、人群包。
- 活动：首页轮播、专题页、优惠券、资源位、投放门店、投放时间。
- 门店：城市、营业状态、取餐时长、库存风险、门店公告。

## 3. 小程序原型规则

- 手机壳居中，左侧使用可收起抽屉导航。
- 导航必须包含一级功能和二级功能，二级功能要能切换页面。
- 顶部要保留小程序胶囊按钮样式。
- 高保真模式展示真实内容、图片、商品、订单、会员信息。
- 低保真模式只保留结构，避免彩色视觉干扰。
- 所有一级入口必须有返回路径或底部导航承接。

## 4. 后台原型规则

- 后台必须是独立项目，不和小程序放在同一个 HTML 中。
- 左侧导航需要支持展开和收纳。
- 运营总览负责全局统计，商品、订单、会员、门店等业务模块不重复堆统计卡片。
- 商品管理应包含分类、筛选、列表、添加商品、库存调整、批量上下架。
- 订单履约应包含履约状态、订单列表、异常处理、门店协同。
- 会员运营应包含会员列表、人群分层、发券任务、历史订单。
- 门店管理应包含门店卡片、营业状态、公告、营业时间和取餐能力。
- 表格行点击后从右侧弹出详情抽屉，展示字段、编辑表单和处理记录。

## 5. 迭代规则

- 修改页面前，先确认所属业务域和关联对象。
- 新增功能前，先检查是否需要同步小程序端和后台端。
- 修改字段前，先检查是否影响表格、详情、筛选和验收清单。
- 每轮完成后检查：导航、主流程、空态、异常态、数据一致性、移动端/桌面端布局。
