# 需求文档：结合自身业务写 PRD 去除 AI 味道

本章节提供一个 `prd-doc-writer` Skill，用于把业务资料、原型、流程图、会议记录或需求池整理成完整 PRD 文档。

## Skill 能做什么

- 根据业务资料生成完整 PRD。
- 参考传统功能需求说明书结构，补齐修订记录、适用范围、名词解释、业务流程、页面元素、业务规则、业务逻辑和验收标准。
- 把不确定信息放入“待确认问题”，避免 AI 编造业务规则。
- 输出更像产品经理写的需求文档，而不是泛泛的 AI 总结。

## 推荐输入

- 产品/系统名称
- 需求名称
- 业务背景
- 目标用户/使用角色
- 原型路径或截图
- 业务流程图
- 会议记录或需求池
- 本期范围和不做范围

## 输出内容

- PRD 文档
- 页面元素表
- 业务规则表
- 状态与异常说明
- 验收标准
- 待确认问题清单
