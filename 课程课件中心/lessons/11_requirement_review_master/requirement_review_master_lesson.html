Review Master

需求评审不是被动挨问，而是提前演练

这一节讲 `pm-review` Skill：用 AI 在评审前模拟前端、后端、设计、测试、业务方、老板 6 个角色，提前发现 PRD 或原型里的漏洞。

核心价值：不是替代评审会，而是让你在评审会上更专业、更从容。

01:30 - 04:00
Pain Point

很多评审会的问题，不是需求差，而是准备不够立体

PRD 通常从产品视角出发，但评审会上每个角色关注点完全不同：研发关心可实现性，测试关心边界，业务关心流程，老板关心投入产出。

会中才暴露

  • 接口和字段没想清楚
  • 异常状态没有设计
  • 权限边界不明确
  • 老板追问价值和优先级

会前先演练

  • 提前模拟角色提问
  • 把阻塞问题先补齐
  • 准备专业回应话术
  • 把评审变成确认和对齐
04:00 - 06:30
Skill Overview

`pm-review` Skill 能做什么？

输入

PRD、需求文档、HTML 原型，或者两者一起提供。

评审

自动选择评审模式，模拟 6 个角色，识别问题并分级。

输出

问题清单、应对方案、追问预判、兜底话术和改进清单。

它不是只挑毛病，而是帮产品经理把“可能被挑战的问题”和“应该怎么回应”一起准备好。
06:30 - 09:30
Three Modes

三种评审模式：有多少资料，就做多少预审

模式输入评审重点适合场景
模式 A：原型评审仅 HTML 原型页面、跳转、交互、四态、场景走查原型先行，还没有完整 PRD
模式 B：PRD 评审仅 PRD / 需求文档6 角色模拟提问、问题分级、应对方案正式需求评审前
模式 C：一致性评审PRD + 原型文档与原型交叉比对，找遗漏和冲突准备进入研发前

16:30 - 19:30
Prototype Review

只有 HTML 原型，也能做有效评审

原型里其实藏着很多需求信息：页面清单、核心元素、跳转关系、表单、列表、弹窗、数据展示和操作路径。

Skill 会强制检查加载态、空状态、错误态、成功态，这是原型评审最容易被忽略的地方。

四态覆盖检查

状态常见缺口评审问题
加载态白屏无反馈数据请求慢时用户看到什么？
空状态列表空白无数据时是否给行动引导？
错误态只有技术报错网络失败能否重试？
成功态无明确反馈操作完成后下一步去哪？
19:30 - 22:30
Mode Switch

不同输入，报告结构也不一样

原型解析摘要

页面清单、跳转关系、交互组件、数据展示。

业务场景评审

模拟真实用户任务，找断头路和信息缺口。

交互自查结果

四态、表单、导航、数据展示和批量操作。

需求摘要

功能清单、核心流程、数据模型、角色权限。

角色评审详情

6 个角色分别提出 3-5 个具体问题。

应对方案

方案、追问预判、兜底话术和改进清单。

一致性问题

PRD 写了但原型没体现，或原型有但 PRD 没写。

PRD 评审

从角色角度检查文档完整度和业务判断。

原型评审

从页面、交互、状态和场景走查体验漏洞。

22:30 - 25:30
Response

真正有用的是：问题后面还有应对话术

评审准备不是把问题列出来吓自己，而是准备“怎么回应、怎么推进、会后谁跟进”。

核心原则：先认可问题，再给方向；不在会上空转，把不确定项落到下一步动作。

PREP

观点 → 理由 → 例子 → 重申。适合说服对方接受方案。

SPIN

场景 → 问题 → 影响 → 收益。适合回应价值质疑。

3C

背景 → 对比 → 选择。适合多个方案取舍。

兜底动作

承认缺口，给方向，指定责任人和下一步。

How To Use

实操时怎么用？

安装 Skill 后，输入 `/pm-review`，再把 PRD 文档、HTML 原型路径或两者一起交给 AI。它会自动选择评审模式。

建议输入越具体越好：产品名称、评审目标、资料路径、关注角色、希望输出格式。
/pm-review 产品名称： 评审目标： 资料类型：PRD / HTML 原型 / PRD + 原型 PRD 路径： 原型路径： 重点关注角色：前端、后端、设计、测试、业务方、老板 输出格式：md / docx / html / 全部 请先输出评审概览，再给出阻塞问题、重要问题、建议问题和应对话术。

Deliverables

最终拿到什么？

评审概览

问题总数、分级分布、涉及功能点、应对覆盖率。

阻塞重要建议

角色问题库

按前端、后端、设计、测试、业务方、老板拆分问题。

应对话术库

每个关键问题给方案、追问预判和兜底话术。

改进清单

按优先级排序，方便更新 PRD、原型和评审纪要。

HTML 报告

适合屏幕展示，支持按角色和严重度筛选。

Word 报告

适合打印、分发、归档和跨团队评审。
