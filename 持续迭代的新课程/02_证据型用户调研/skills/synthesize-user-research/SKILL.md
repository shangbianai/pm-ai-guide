# AI 用户调研分析

把混合研究素材转化成可审计的研究结论。先保全证据，再形成洞察；不要从画像模板反推用户。

## 快速开始

接受文件或目录。最小输入为一种含用户原话的材料；推荐同时提供访谈、观察和行为/业务记录。

一句话调用示例：

> 使用 `$synthesize-user-research` 分析这个素材目录，生成有证据出处的客户画像、用户旅程、3 个关键断点和机会排序，并把分析结论、原始配图、访谈音频及完整转写同步到飞书文档。

默认在输入目录旁创建 `research-output/`。不覆盖已有结果；存在时创建带时间戳的新目录。

## 工作流

### 1. 盘点素材

- 列出每个文件的类型、可读状态和分析用途。
- 为来源分配 `SRC-001` 起的编号。
- 音频有现成转写时优先核对转写；没有时使用可用的本地转写能力。
- 照片只记录可见事实；不要根据装修、穿着或物品推断收入、性格等属性。
- 表格检查缺失、重复、命名不一致和异常值。疑似同一对象只标记为候选重复，不自动合并。
- 发现真实姓名、手机号、健康、财务等敏感信息时，在输出中脱敏。

### 2. 建立证据台账

- 为证据分配 `E-001` 起的编号。
- 每条证据保留 `source_id`、定位信息、原文或可见事实、证据类型。
- 音频使用时间戳；转写使用段落/说话人；表格使用行号/字段；图片使用区域描述。
- 原文摘录保持短小，不为了让结论成立而改写原意。

### 3. 分离事实、推断与假设

- `已验证事实`：素材直接出现，必须引用证据。
- `合理推断`：由两条以上证据支持，必须写明推理边界。
- `待验证假设`：证据不足或可能有其他解释，必须给出验证方法。
- 单个受访者不能代表整个市场。使用“本次受访者”“当前样本”而不是“所有用户”。
- 客户提出的功能方案与其背后的任务/需求分开记录。

### 4. 生成研究产物

按 [output-contract.md](references/output-contract.md) 创建 `research-bundle.json`，至少包含：

- 素材清单与证据台账
- 矛盾、重复候选和信息缺口
- 证据约束的客户画像
- 5—7 阶段的用户旅程与情绪值
- 3 个关键体验断点
- 机会排序；机会描述用户结果，不直接写成按钮或页面
- 5 个下一轮研究问题

每条画像声明、事实型洞察、旅程痛点和机会必须引用 `evidence_ids`。没有证据时保留为空并标记待验证。

### 5. 校验与渲染

运行：

```bash
python3 scripts/validate_research_bundle.py /absolute/path/research-bundle.json
python3 scripts/render_research_report.py \
  /absolute/path/research-bundle.json \
  /absolute/path/research-report.html
```

Chrome 可用且需要直播/PPT预览时运行：

```bash
python3 scripts/capture_report.py \
  /absolute/path/research-report.html \
  /absolute/path/research-report.png
```

修复所有校验错误。警告需要在报告的“研究限制”中可见，不得静默忽略。

### 6. 输出交付物

必须输出：

- `research-bundle.json`：唯一结构化数据源
- `research-report.html`：可交互证据型调研报告
- `research-report.md`：便于复制和评审的文本报告
- `source-manifest.md`：素材清单、读取状态和隐私说明

Chrome 可用时增加 `research-report.png`。

### 7. 完整同步到飞书

用户明确要求写入飞书时，读取并使用 `lark-doc` Skill 和 `/opt/homebrew/bin/lark-cli`。先完成本地校验，再按以下顺序执行；不要只同步分析结论：

1. 在 `research-bundle.json` 添加 `feishu_sync`，按 [output-contract.md](references/output-contract.md) 列明完整转写和每个待上传媒体。
2. 生成飞书 XML，正文依次包含分析结论、画像、旅程、机会、研究限制和“完整访谈转写”。转写必须写入正文，不能只作为附件。
3. 一级标题统一使用阿拉伯数字序号，如 `1. 30 秒结论`、`2. 客户画像`；不得出现无编号的一级标题或跳号。
4. 证据不能只显示 `E-003`。画像、发现和机会中的证据至少写成 `E-003｜用户原话或事实摘要｜来源文件｜定位`；原话保持简短但足以让读者理解。
5. 适度强调关键决策和风险：用 `<b>` 加粗核心判断，用 `<span text-color="red">` 标红高风险、冲突、不可泛化结论。标红必须克制，不能把整段或整表染红。
6. 在“原始调研素材”章节先创建总表，列出来源编号、文件名、类型、内容摘要、关联证据、飞书呈现方式和上传状态。表格每一行对应一个输入文件。
7. 用 `docs +create --as user` 创建文档，记录返回的 `document_id` 和 URL。
8. 对每张本地图片运行 `docs +media-insert --type image`。caption 使用 `来源编号｜内容说明｜关联证据 E-xxx`，默认宽度 900、居中；图片嵌入即视为该文件已上传。
9. 对音频、转写、观察笔记、CSV 和其他输入原文件逐一运行 `docs +media-insert --type file`，保留原始文件名。除用户明确排除、文件含未获授权的敏感信息或平台不支持外，输入目录中的每个文件都必须上传；转写既写入正文，也保留原始附件。
10. 使用 `docs +fetch --detail simple` 回读整篇，确认：一级标题连续编号；存在完整转写章节；素材总表覆盖所有输入文件；`<img>` 数量等于计划图片数；`<source>` 数量等于计划附件数。缺一项不得报告同步成功。
11. 保存 `feishu-sync-result.json`，记录 URL、文档 ID、标题编号校验、转写状态、素材表覆盖率、每个媒体的 block ID/file token 和回读校验结果。

认证、权限或单个媒体上传失败时，保留本地交付物，在同步结果中逐项标记失败，不声称完整同步成功。媒体路径使用 CLI 要求的当前工作目录相对路径。

## 判断标准

- 结论可点击或可查到原始证据，而不只是“看起来合理”。
- 画像只保留影响产品决策的特征。
- 情绪最低点不自动等于最高优先级。
- 客户说“想要自动发送”不等于必须做自动发送；同时检查风险与控制需求。
- 输出先回答“发生了什么、为什么重要”，再讨论“做什么功能”。
- 素材不足仍然可以输出，但必须降低证据强度并提出验证计划。
- 要求飞书同步时，文档必须能独立复核：看得到配图、下载得到原始音频、读得到完整转写。
- 证据对人可读：编号只是索引，原话/事实摘要、来源文件和定位才是解释。
- 原始素材表一行对应一个输入文件；表中“已上传”必须有回读到的图片或附件块支持。
