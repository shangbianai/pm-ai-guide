WHY

为什么需要 HTML 报告？

当内容既要有结构、又要有图表、还希望别人能直接在浏览器里阅读时，HTML 报告是一个很轻的交付方式。

  • 比纯 Markdown 更适合老板和业务方阅读。
  • 比 PPT 更适合承载长内容和细节数据。
  • 比 Word 更容易加入交互图表和目录导航。

市场、行业、竞品、用户研究都可以生成网页版报告。

标注讨论

CAPABILITY

这个 Skill 能做什么？

它不是从零写一个网页，而是基于固定模板，把内容填进专业的 HTML 报告结构里。

左目录 + 右内容自动生成目录，滚动时高亮当前章节。
指标卡把关键结论、数字和说明放在顶部。
原生图表柱状、折线、饼图、雷达、散点，零依赖。
结构图示产业链、生命周期、流程链、思维导图等。
浏览器标注画笔、高亮、批注、导入导出、localStorage 保存。
响应式换肤桌面、平板、手机适配，CSS 变量可换色。
WORKFLOW

标准工作流：只改关键位置

Agent 不需要重写整套网页，只需要围绕模板编辑四类内容。

1

明确报告内容

标题、受众、素材来源、章节和图表类型。

2

读取模板

理解 assets/template.html 的结构。

3

填充正文和数据

修改 Hero、正文章节、指标卡、REPORT_DATA。

4

交付单文件

输出一个完整 `.html` 文件，浏览器打开即可阅读。

TEMPLATE

报告结构：内容和数据分开

这个 Skill 的好处是结构清晰：正文写在 <main>，图表数据写在 REPORT_DATA，参考链接写在 REF_LINKS。

<header class="hero">
  报告标题 / 摘要 / 元信息
</header>

<main class="content">
  <div id="metric-grid"></div>
  章节正文：h1 / h2 / p / table / blockquote
  图表占位：<div id="fig1" data-chart="barline">
</main>

<script>
  const REPORT_DATA = { ... };
  const REF_LINKS = { ... };
</script>

SUMMARY

回顾重点：这节课的价值

HTML 报告生成 Skill 适合把“长内容 + 数据图表 + 阅读导航 + 标注讨论”合成一个轻量交付物。

  • 报告不是只有 Word 和 PPT 两种形态。
  • HTML 报告适合承载长分析和交互图表。
  • 模板化让输出更稳定，也方便换肤和复用。
  • 接下来可以用一份调研材料跑出完整报告。

一句话带走

当你要把调研、分析、复盘变成可阅读、可分享、可标注的网页时，就可以用这个 Skill。
