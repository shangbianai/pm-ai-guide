Market Insight Skill

用一个 Skill 做出老板愿意看的市场洞察

这一节我们讲市场洞察 Skills。它不是让 AI 写一篇行业作文，而是把行业趋势、用户变化、竞品动作、业务机会四类输入，转成能进入评审会的洞察报告。

重点不是模型名有多高级，而是补上产品经理最容易缺的两件事：业务判断和老板决策建议。

本节课一句话：让 AI 不只“分析”，还要帮我们“判断该不该做、先做什么、不做什么”。

本节课最终讲清楚

从 skill 能力、实现结构到实操路径，学员能直接复刻。

Why Skill

为什么不用普通 Prompt，而要做成 Skill？

普通 Prompt 最大的问题是每次都要重新解释工作流，而且模型容易把 SWOT、PESTEL 变成机械填表。Skill 的价值，是把角色、输入、方法论、输出结构和脚本生成流程固定下来。

普通 Prompt 常见问题

  • 结论像行业作文
  • 章节堆模型，缺少叙事
  • 没有区分事实、推断、待验证
  • 最后不给老板可拍板建议

Skill 固化什么

  • 角色：产品战略顾问
  • 输入：产品、行业、资料、目的
  • 流程：先分析，再综合，再判断
  • 交付：HTML 决策报告

课程要强调什么

  • 模型只是幕后工具
  • 报告要按决策叙事组织
  • PM 要用 AI 逼近业务判断
  • 最终要能指导行动
Inputs

这个 Skill 主要吃四类输入

市场洞察不是凭空生成。我们要把输入拆成四类，让 AI 知道从哪里找信号、怎么交叉验证、最后如何形成判断。

关键判断：资料越贴近真实业务，报告越不像套话。

行业趋势

政策、技术、资本、渠道、宏观环境变化。回答“为什么是现在”。

用户变化

用户行为、需求迁移、付费意愿、使用场景变化。回答“谁真的痛”。

竞品动作

竞品发布、定位变化、价格策略、渠道打法。回答“对手在往哪打”。

业务机会

我方资源、客户线索、现有能力、增长瓶颈。回答“我们能切哪里”。

Behind The Scenes

方法论在幕后，不直接堆在报告里

这个 Skill 最关键的设计，是把 SWOT、PESTEL、KANO、优先级矩阵当成分析引擎，而不是报告目录。老板不关心你用了几个模型，老板关心结论能不能拍板。

PESTEL

扫描外部推动力：政策、经济、社会、技术、环境、法律。

SWOT / TOWS

把我方能力和市场机会组合起来，形成策略打法。

KANO

判断需求是入场券、满意度杠杆，还是差异化惊喜。

优先级矩阵

把业务价值、可行性、风险和周期放到同一张表里。

讲法建议：不要说“AI 帮我套模型”，要说“AI 用模型帮我支撑判断”。
Report Spine

最终报告不是模型合集，而是一条决策叙事

Skill 规定了 8 个核心章节，从一页纸执行摘要开始，到行动路线图结束。这样的结构非常适合向老板汇报：先给结论，再给依据，最后给行动。

0执行摘要一句话结论 + Top 3 行动。
1市场全景市场规模、增长、玩家、阶段。
2环境扫描外部力量如何推动或阻碍。
3能力审视优势、劣势、机会、威胁。
4用户需求基本型、期望型、兴奋型需求。
5综合洞察行业、用户、竞品、业务机会。
6业务判断价值、可行性、风险、关键假设。
7行动方案做什么、不做什么、节奏怎么排。
A监测计划信号、数据来源、检查频率。
Implementation

这个 Skill 在 GitHub 里到底长什么样？

它不是只有一个提示词文件，而是由主指令、方法论参考、生成脚本、报告模板组成的一套小型交付系统。

理解这个结构之后，学员就能知道：哪些内容负责“让 AI 会分析”，哪些内容负责“让报告稳定生成”。

Root Path skills/market-insight/ 市场洞察 Skill 的完整目录。真正要理解的是：每个文件都对应一个稳定职责。
第1章_市场洞察/ └── 02_市场洞察Skills/ └── skills/ └── market-insight/
SKILL.md定义 AI 的角色、输入要求、分析流程、报告结构和关键约束。
reference/存放 SWOT、PESTEL、KANO 等方法论说明，供模型调用。
scripts/存放生成脚本，把结构化 JSON 转成可看的 HTML 报告。
assets/存放 HTML 报告模板，决定最终报告的视觉和版式。
1 Input业务资料产品、行业、用户反馈、竞品动作、分析目的。
2 SkillSKILL.md约束 AI 按固定流程完成分析，而不是自由发挥。
3 MethodReference调用 SWOT、PESTEL、KANO 等幕后框架支撑判断。
4 DataJSON把结论整理成稳定字段，方便脚本读取。
5 OutputHTML 报告脚本套模板生成可汇报、可交付的市场洞察。
核心逻辑：AI 负责判断和结构化，脚本负责稳定交付。
BrainSKILL.md 是“大脑”告诉 AI 该扮演谁、问什么、按什么章节输出、哪些红线不能碰。
Knowledgereference 是“方法库”把 SWOT、PESTEL、KANO 的分析逻辑沉淀下来，减少每次重复解释。
Enginegenerate-report.py 是“引擎”读取 JSON，替换模板变量，生成最终 HTML 文件。
Skinreport-template.html 是“外观”统一报告样式，保证每次输出不跑偏，也方便后续升级视觉。
记住一句话：Skill = 分析规则 + 方法论 + 生成器 + 模板。
Generation Rule

关键约束：报告必须通过脚本生成

这个 Skill 里有一个很重要的工程化约束：不要让 AI 自己手写 HTML。AI 负责分析和整理 JSON，脚本负责把 JSON 填进模板。

这就是课程里可以强调的“产品经理也要懂一点工程化思维”：把不可控的生成，变成可复用的流程。
# 1. AI 先整理结构化数据 { "product": "产品名称", "executive_summary": { "conclusion": "一句话结论", "top_actions": [ {"priority": "P0", "action": "行动内容", "effect": "预期效果"} ] }, "business_judgment": { "risks": [], "assumptions": [] }, "decision": { "actions": [], "not_do": [], "roadmap": [] } } # 2. 再用脚本生成 HTML 报告 python3 skills/market-insight/scripts/generate-report.py \ 产品-data.json 市场洞察报告_产品_日期.html
How To Use

实操前先搞清楚：这个 Skill 怎么安装、怎么调用？

使用路径很简单：先把 `market-insight` 复制到 Claude Code 的 skills 目录，然后在对话里明确说“使用 market-insight skill”，再补充产品、行业、资料和分析目的。

Demo Scenario

从碎片资料到老板决策页

我们用一个具体业务场景来跑通，比如“连锁口腔机构 AI 线索分析产品”。先把行业趋势、用户反馈、竞品动作和我方业务机会输入给 skill，再让它输出市场洞察报告。

输入示例内容AI 应该产出什么判断
行业趋势线上获客成本上升，机构更关注有效线索和转化质量。市场从“买流量”进入“提转化”阶段。
用户变化咨询团队被重复线索、低意向线索和话术质检拖累。痛点不是缺线索，而是线索质量和承接效率。
竞品动作CRM 和营销工具多记录结果，较少分析对话内容和掉点原因。可以从“AI 线索洞察 + 咨询质检”切入。
业务机会客户愿意为到店率提升、咨询效率提升评估预算。MVP 要绑定业务指标，而不是做大而全 CRM。
Boss Page

真正值钱的是“老板决策建议”

这类报告最后一定要落到一句话：建议做什么、为什么现在做、先投入多少资源、多久看结果。否则就是分析很漂亮，但决策没发生。

市场洞察不是给老板看“我很努力查了很多资料”，而是让老板看完知道：这件事值不值得做，如果做，第一步怎么做，什么情况应该停。
P0：先做 30 天验证选择 2 家门店、3 个渠道，验证线索清洗和咨询质检对有效到店率的影响。
P1：搭建轻量看板展示渠道质量、线索重复、意向等级、咨询跟进质量，服务周会复盘。
P2：扩展到多门店验证有效后再复制到区域门店，避免一开始做全量系统替换。
NOT TO DO暂不替换 CRM，不做复杂排班，不把 AI 质检直接变成强考核。
Advantages

这个 Skill 的优势：快，但不是浅

它的价值不是“自动写报告”这么简单，而是把产品经理做市场判断时的一套思考路径固化下来，让每次输出都更接近可汇报、可讨论、可行动。

结构稳定

输入、分析、判断、行动都有固定路径，减少每次从零写 Prompt 的成本。

方法完整

SWOT、PESTEL、KANO、优先级矩阵共同支撑结论，而不是各讲各的。

交付专业

通过模板生成 HTML 报告，视觉和信息结构更适合汇报。

逼近决策

要求量化业务价值、识别风险、写清 NOT TO DO，避免空泛建议。

可复用

换行业、换产品、换资料，也能沿用同一套分析框架。

可迭代

后续可以继续往 reference 里补行业方法论、案例和模板。
