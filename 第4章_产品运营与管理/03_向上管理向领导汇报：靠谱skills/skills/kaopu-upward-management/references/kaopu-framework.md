# 《靠谱》方法论蒸馏：向上管理版

本文件为《靠谱：顶尖咨询师教你的工作基本功》的方法论蒸馏，用于向上管理、汇报、请示和工作推进。这里只保留可操作原则，不复制书中正文。

## 1. 结论先行

向上沟通时，对方最关心的是“所以呢”。先说结论，再解释理由。

可用结构：

- 结论：建议做 / 不建议做 / 当前完成 / 当前未完成。
- 理由：用 2-3 条事实支撑。
- 行动：下一步怎么做，需要谁决策。

常见错误：

- 先讲背景，讲了很久还不知道要什么。
- 汇报像流水账，没有结论。
- 把“我很努力”当成结果。

## 2. Talk Straight

直入主题，坦率、简洁、明确。尤其是延期、失败、资源不足、方向错误时，不要绕弯。

表达方式：

- “结论是：目前还没有完成。”
- “原因不是执行拖延，而是数据口径还没统一。”
- “如果要按原时间交付，需要增加 1 名同事支持。”
- “如果不能加人，建议把范围缩到 A 和 B，C 放到下一版。”

关键点：

- 坏消息先说事实，再说影响和方案。
- 不把原因讲成借口。
- 发现上级判断有明显问题时，要基于事实提出提醒。

## 3. 数据和事实是新人/下级最稳的武器

向上沟通不要只说“我感觉”“大家反馈”“可能有问题”。要尽量把主观判断落成事实和数据。

可用证据：

- 用户反馈数量、转化率、留存、耗时、成本、错误率。
- 具体案例和原始截图。
- 访谈摘录、工单、日志、埋点。
- 竞品动作、行业事实、历史对比。

表达方式：

- “过去 7 天共有 38 条用户反馈，其中 21 条集中在导出失败。”
- “3 个测试账号都复现了同一问题。”
- “如果继续按当前方案做，预计至少多 2 天联调。”

## 4. 云-雨-伞：事实、分析、行动建议

云：事实。发生了什么。

雨：分析。事实说明什么，风险是什么，原因是什么。

伞：行动。建议怎么做。

汇报时三者都要有：

- 只有云：像搬资料，领导还要自己分析。
- 只有雨：像主观判断，缺少证据。
- 只有伞：像拍脑袋行动，缺少依据。

标准句式：

```text
事实是：……
我的判断是：……
建议动作是：……
需要您确认的是：……
```

## 5. 期望值管理

很多不靠谱不是能力问题，而是没有对齐对方真正要什么。开始做之前先确认四件事：

- 目标：这件事最终要解决什么问题？
- 范围：做到什么程度算够？哪些不做？
- 质量：要 60 分快速版本，还是 100 分正式版本？
- 时间：什么时候必须交？截止日期是否绝对？

向上汇报时也要管理期望：

- 哪些已经完成。
- 哪些还在进行。
- 哪些存在风险。
- 下一次同步时间是什么。

## 6. 逻辑先行，让对方听得懂

成熟表达不是堆术语，而是让对方能快速理解。

实践要求：

- 一页只讲一个核心观点。
- 每段只服务一个结论。
- 少用内部黑话，多用低语境表达。
- 面向对方的背景组织语言。

## 7. 假设-检验-反馈

遇到复杂问题，不要无限收集资料。先建立假设，再验证，再修正。

向上管理表达：

```text
我现在的假设是……
目前验证到的事实是……
这个假设成立/不成立。
下一步我会验证……
```

## 8. 承诺推进

靠谱的人不会只说“我再看看”。要给出明确的下一步。

最小承诺结构：

- 下一步动作：
- 负责人：
- 截止时间：
- 需要支持：
- 下次同步：

## 9. 常见场景模板

### 进度正常

```text
结论：当前进度正常，预计按计划在 X 月 X 日交付。
事实：A 已完成，B 正在联调，C 还未开始但不影响关键路径。
风险：目前主要风险是……
下一步：今天完成……，明天同步……
```

### 进度延期

```text
结论：当前版本无法按原计划在 X 日完整交付。
事实：主要卡点是……，目前影响范围是……
原因：不是……，而是……
方案：建议采用方案 A，先保证……；方案 B 作为备选。
需要您确认：是否同意将……调整到下一版。
```

### 请求资源

```text
结论：如果目标不变，需要增加……资源。
事实：当前剩余工作量为……，现有人力预计需要……天。
影响：不增加资源会导致……
方案：A 增加……；B 缩小范围……；C 延后时间……
建议：我推荐 A/B，原因是……
```

### 发现方向问题

```text
结论：我建议暂缓当前方向，先确认……。
事实：目前发现三个信号……
分析：这些信号说明原假设可能不成立。
建议：先用一天验证……，再决定是否继续投入。
```
