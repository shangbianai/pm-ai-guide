# PMBOK 项目管理框架提炼

本文件用于课程和 Skill 的高层参考，不复制 PMBOK 原书正文，只沉淀可用于产品经理项目管理场景的结构化框架。

## 一、五大过程组

| 过程组 | 管理重点 | 产品经理常见问题 | 可生成产出 |
|---|---|---|---|
| 启动 | 目标、授权、商业价值、相关方 | 为什么做？谁拍板？成功标准是什么？ | 项目目标、章程草案、相关方列表 |
| 规划 | 范围、进度、资源、风险、沟通 | 怎么拆？多久做完？谁负责？风险在哪？ | WBS、里程碑、风险登记册、沟通计划 |
| 执行 | 团队协作、质量保障、资源协调 | 谁卡住了？质量怎么守住？ | 阻塞清单、责任矩阵、质量检查点 |
| 监控 | 偏差、变更、风险升级、状态同步 | 是否延期？是否需要变更？ | 偏差分析、变更影响、项目周报 |
| 收尾 | 验收、移交、复盘、经验沉淀 | 是否验收？后续谁接？ | 验收清单、移交计划、复盘报告 |

## 二、十大知识领域

1. 整合管理：把目标、范围、进度、成本、风险放在一起判断。
2. 范围管理：明确做什么、不做什么，形成可验收边界。
3. 进度管理：拆活动、排依赖、识别关键路径。
4. 成本管理：判断预算、人力和机会成本。
5. 质量管理：定义质量标准、测试策略和验收门禁。
6. 资源管理：识别人员能力、投入比例和负载冲突。
7. 沟通管理：明确谁需要知道什么、何时同步、用什么形式。
8. 风险管理：识别概率、影响、触发信号和应对动作。
9. 采购管理：管理外部供应商、系统依赖和 SLA。
10. 相关方管理：识别权力、利益、态度和影响策略。

## 三、产品经理最常用的 PMBOK 转换

- 项目章程 -> 项目背景、目标、边界、成功标准。
- WBS -> 功能拆解、任务拆解、交付物拆解。
- 进度基线 -> 里程碑、关键路径、延期预警。
- 风险登记册 -> 风险、概率、影响、负责人、应对动作。
- 沟通计划 -> 周会、日报、评审会、领导同步口径。
- 相关方矩阵 -> 老板、业务、研发、测试、运营、客户的沟通策略。
- 收尾过程 -> 验收、交接、上线复盘、经验库。

## 四、导师式回答原则

- 先定性：这是范围问题、进度问题、资源问题、风险问题，还是相关方问题。
- 再定量：影响哪些里程碑、多少人天、哪些交付物。
- 给选项：保日期、保范围、保质量，分别需要什么取舍。
- 给话术：对老板、业务方、研发团队的表达不能一样。
- 给动作：把建议落到责任人、截止时间和交付物。
