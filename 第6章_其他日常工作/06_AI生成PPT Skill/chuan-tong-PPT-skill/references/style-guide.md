# Style Guide

## Overall Look

- Corporate consulting/report style, not a marketing landing page.
- White canvas, restrained blue accents, thin top divider line, generous whitespace.
- Visual density is medium: concise title and one central body region per slide.
- Avoid colorful decorative clutter. The template's blue blocks and top rule are the main chrome.

## Colors

Use the source colors as the first choice:

- Primary blue: `#0061AE`
- Deep blue: `#054487`
- Mid blue: `#0070C0`
- Light blue: `#65B4D5`
- Pale grey background: `#F2F2F2`
- Body black/grey: `#000000`, `#333333`, `#6E747A`
- White: `#FFFFFF`

Do not turn the deck into a one-note gradient-heavy tech deck. Keep blue accents sparse and structural.

## Typography

Source fonts include:

- `Calibri`
- `微软雅黑`
- `字魂手刻宋`

Preserve inherited font family, font size, alignment, line spacing, and text-box insets. If new text does not fit, shorten it, split the slide, or choose a better source slide.

### Emphasis

- Use bold weight to make the core conclusion scannable.
- Use primary blue for target capabilities, opportunity language, and strategic recommendations.
- Use restrained red only for negative pressure, risk, mismatch, or urgent constraints.
- Keep emphasis sparse: 1-3 highlighted phrases per content slide is usually enough.
- Avoid mixing too many emphasis colors in one sentence.

## Content Style

- Use short Chinese business-report phrasing.
- Lead with the conclusion in the title.
- Body copy should be compact and factual.
- Use 熵变智元 as the default company/brand name unless the user supplies another brand.
- Use terms like AI 智能体, 数据智能, 产业互联网平台, 数据底座, 能力体系, 生态协同, 智能化运营 only when relevant to the user's topic.
- Keep the section divider pages sparse: chapter label plus chapter title only.

## Image Style

Generated images should feel like enterprise technology visuals:

- clean, credible, industrial or city/service setting when relevant,
- blue-white palette compatibility,
- no embedded readable text unless the user explicitly requests post-processing text insertion,
- no fake logos, fake screenshots, fake charts, fake QR codes, or fake official marks,
- enough negative space for the target crop.

For dashboard/product UI pages, prefer using user-provided screenshots. If none are provided, generate abstract data-platform visuals rather than fake UI screenshots.

Generated images should be layout-native:

- Align to a chart, matrix, flow, or text card instead of floating in unused space.
- Use a consistent small image-card treatment for inline images: white backing, thin pale-blue border, 4-6 px corner radius, subtle shadow only when the source template already uses shadows.
- Use captions as editable PPT text, not baked into the image.
- Size images by their communicative role. Small inline images should usually occupy one card width or a side-panel width; hero images should use a dedicated large-visual source slide.
