# AI 原型设计 User Rules

这份文档适合放入 Cursor / Codex / Claude 项目的用户规则中，用来约束 AI 生成原型时的审美、结构和交付方式。

## 通用偏好

- 不要只做静态页面，要做可点击、可切换、可验证的原型。
- 不要把小程序和后台混成一个项目，两个端应该独立交付。
- 不要只追求视觉，要优先保证业务结构、流程闭环和数据一致。
- 页面内容要像真实业务系统，不要出现模板感很重的占位文案。
- 重要交互要能演示：导航切换、列表筛选、详情抽屉、状态切换、表单编辑。

## 小程序偏好

- 手机壳居中，外观接近真实手机。
- 左侧导航是抽屉菜单，可以展开和收起。
- 底部导航不要使用粗糙矩形选中态，更接近小程序真实风格。
- 高保真要有 banner、图标、商品图、订单和会员信息。
- 低保真必须黑白灰，不出现彩色。

## 后台偏好

- 后台整体要像标准 B 端系统，左侧导航、顶部操作、筛选表单、数据表格、右侧详情抽屉都要完整。
- 左侧导航必须支持收纳，收起后保留图标。
- 运营总览展示全局指标和跨模块风险。
- 商品、订单、会员、门店等模块要根据业务差异做不同布局，而不是只换数据。
- 列表页要有新增、导入、导出、批量操作、筛选、字段设置等常见后台动作。

## 交付偏好

- 需要提供 HTML 文件和压缩包。
- 需要提供项目规则 MD、用户规则 MD、提示词模板和验收清单。
- 课程 PPT 中不要出现幕后制作视角的字眼。
