Problem

传统竞品分析，最容易卡在三件事

第一，资料散：官网、截图、应用商店评价、行业文章都在不同地方。

第二，维度乱：今天比功能，明天比价格，最后很难形成统一判断。

第三，结论弱：写了很多“竞品 A 做得好”，但没有告诉团队下一步怎么做。

只列功能

知道竞品有没有，但不知道用户觉得好不好。

只看宣传

官网说的是卖点，用户吐槽才是机会。

只做截图

页面长得像，不代表业务定位一样。

只给描述

老板要的是判断：跟进、差异化，还是暂不做。

Capability

这个 Skill 能做什么？

`pm-compete` 输入竞品名称、链接、截图、体验笔记或已有文档，输出功能矩阵、用户口碑对比、定位图、价值曲线、ERRC 行动框架和机会点建议。

它不是“生成一篇介绍竞品的文章”，而是生成一份可以进入产品决策讨论的分析底稿。

输入

竞品名、官网链接、截图、体验笔记、研究文档。

分析

功能、口碑、定位、价值曲线、差异化机会。

输出

Markdown 报告、功能矩阵、Word 报告、Excel 表格。

Mode

两种工作模式：首次建立，持续更新

竞品分析不是做完就结束。一个新版本发布、一个新玩家入局，都可能让原来的判断过期。

首次建立竞品分析

当 `_pm_context/competitive/competitive-analysis.md` 不存在时，Skill 会从头理解产品、竞品和分析目的，生成完整分析框架。

Framework

五层分析，回答五个问题

层次方法回答的问题对产品决策的价值
01功能矩阵竞品有没有这个功能？快速看出核心能力缺口。
02用户口碑这个功能做得好不好？发现官网宣传和真实体验的落差。
03定位图我们和竞品站在哪个位置？判断是在扎堆区，还是有空白区。
04价值曲线哪些竞争要素值得投入？避免每个维度都平均用力。
05ERRC该消除、减少、提升、创造什么？从“抄竞品”变成“做取舍”。
Matrix

功能矩阵：不只是打勾

功能矩阵的价值在于统一比较标准。每个格子必须有标记：完整支持、部分支持、不支持，或者信息不足。

关键点：如果竞品“有这个功能”，但用户普遍吐槽体验差，矩阵里就不应该简单打 ✅。
功能点己方客如云简道云判断
外卖订单同步🔶✅❌客如云核心壁垒，己方需评估优先级。
门店库存记录✅✅✅基础能力，差异不在“有没有”。
POS 收银/点单❌✅❌不符合己方轻量后台定位。
移动端体验★★★★★★★★★★己方可以放大“轻量易用”。
Position

定位图：看清楚你到底在跟谁竞争

示例报告用两个轴做判断：功能广度和开箱即用程度。这样就能看出己方不是简单追客如云，也不是复制简道云。

好的定位图要能逼出一句策略：我们处在哪个空白地带？这个空白是机会，还是陷阱？

ERRC

ERRC：竞品分析最后要落到取舍

很多团队做竞品分析，最后变成“别人有的我们也要有”。ERRC 的价值是让你同时思考消除、减少、提升和创造。

消除

POS 收银、前厅点餐、硬件绑定，这些不符合轻量后台定位。

减少

减少大而全倾向，只聚焦 10-50 家门店的核心运营。

提升

提升小程序体验、库存可靠性和透明定价。

创造

创造“极简门店运营”的新定位，避开重型餐饮 SaaS 红海。

Decision

老板关心的不是竞品资料，而是行动建议

这就是 `pm-compete` 的重点：最后把分析转成 P0/P1/P2 和暂不做，让团队知道资源该往哪里放。

优先级行动建议理由
P0保持极简定位用体验和轻量化避开客如云的大而全。
P1评估外卖订单同步这是客如云吸引连锁客户的核心卖点之一。
P1建立透明定价正面回应隐性收费带来的用户不信任。
暂不做POS/硬件/前厅点餐不符合轻量管理后台定位。
Practice

实操时怎么用？

最简单的方式：告诉 AI 我方产品、竞品列表、分析目的和已有资料。如果已经有上一节课输出的功能清单，把文件路径给它。

输入越贴近真实业务，输出越像产品判断；输入越像空泛题目，输出越像泛泛报告。
产品：连锁门店运营管理系统 竞品：客如云、简道云、美团餐饮管家 目的：找出我们的差异化机会和功能优先级 侧重：功能矩阵、用户口碑、外卖订单同步、轻量化定位 资料：_pm_context/requirements/feature-list.md
